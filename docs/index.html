The LLM became
a decision function.

Normally Gemma talks. Here, talking is removed from the hot path. The model reads a state and a question, performs one forward pass, and we read only the logits for the legal answers. No decoding. No JSON. No parser.

Each label must be exactly one token at the real answer boundary. The program verifies that at startup and refuses labels that tokenize any other way.

Typed answers

Following Jev's interface shape, every question is one of three primitives. Each answer carries the full restricted distribution, so the calling code gets a value and a shape, never a sentence.

The score is fractional, so a distribution split between two adjacent levels lands between them instead of snapping to one. Confidence is the largest probability in the restricted set — our own shape statistic, not a calibrated guarantee.

The generation baseline runs the same model on the same prompt and is reported honestly: it emits only two tokens, so the gap is modest. The structural win is that there is no text to parse and the output space cannot go out of range.

What the stress suite found

A prompt hint was quietly breaking the model

An earlier prompt carried a policy hint about retries. It pushed the model toward one answer and dropped option-order stability to 20% and the labelled check to 3/4. Removing it restored 100% stability and 4/4. Rotating the options is what exposed it.

  order  failure_kind     picks: dependency, dependency, dependency, dependency  letters: BADC
  order  retry_unchanged  picks: yes, yes                                      letters: BA
  order  first_owner      picks: security team, security team, security team   letters: CBA
  order  made_progress    picks: yes, yes                                      letters: BA
  option-order stability: 7/7 rotations kept the same decision (100%)

The letters move while the picks stay put — the model is tracking what the labels mean, not where they sit.

And one answer is still wrong

The model says yes, retry the unchanged command — wrong for a deterministic missing library. Order testing confirms this is a genuine model judgment, not position bias, so it is documented rather than patched with leading prompt wording.

Run it

git clone https://github.com/zozo123/gemma-to-jev
cd gemma-to-jev

cargo run --release                 # the demo
cargo run --release -- --stress     # determinism, order stability, spot-check
cargo run --release -- --baseline   # compare against real generation

First run pulls ~2.3 GB of Q4_K_M weights from Hugging Face. Metal is used when available, otherwise --cpu.

Limitations

  • These are not calibrated probabilities. They are model-relative scores from a softmax over the legal labels. The frequent 100% readings reflect a peaked distribution, not certainty about the world.
  • This is Jev-like, not Jev. It borrows the architectural idea and the interface shape. It does not reproduce TypeSafe's model, training, or calibration.
  • Questions run sequentially. Candle's quantized Gemma exposes no cache reset and no ragged attention mask, so fused batching needs upstream support.
  • Routing quality is a 4-bit 4B model's quality. It sends a missing -lssl to the security team, which is defensible but debatable.
